RG2002: Configuration must classify the complete Lake surface🔗

Development documentation generated from commit c7442d95759b with Lean 4.34.0; linter version unreleased (no released package). Moving route: /regula/dev/rules/RG2002/. Snapshot route for this commit: /regula/rev/c7442d95759b…/rules/RG2002/. Once this commit is published, its snapshot is kept by every later deployment. See versions and evidence.

Problem. The surface manifest (foundation_manifest.json, schema 2) is invalid or does not classify every root-package library and executable exactly once.

Action. Fix the manifest: exactly the four top-level keys, one entry per root lean_lib and lean_exe (claimed or excluded with a rationale), and valid claim and execution values.

What triggers it🔗

The checker parses the manifest and reconciles it with Lake's elaborated root package. Unknown keys, duplicates, a wrong schema version, an unknown execution value, an empty surfaces array, a missing rationale, an unclassified or unknown target, and claimed/excluded conflicts are rejected (manifest-schema, manifest-incomplete and related subreasons).

In the editor, an invalid local request (for example an unknown regula.localFoundation value) is reported under this rule for the current file only.

Why it matters🔗

Coverage is only meaningful against a complete, exact classification. Silently ignoring an unknown key or an unclassified target would let modules escape the audit or let a typo change the claim.

How to fix it🔗

  1. Remove or correct unknown keys and invalid values; the diagnostic names them.

  2. Add each root library and executable to surfaces or to the matching exclusion array, with a rationale.

  3. A claimed executable must be a standalone root such as Main; its root module cannot belong to a manifested library.

  4. Run lake lint -- --explain-config to see the manifest, scope, profiles and stages the driver would use, without auditing.

Required proof shape🔗

No proof obligation: the rule concerns configuration. At least one nonempty library surface is required by the schema.

What a passing result establishes🔗

The manifest has the exact schema and classifies every root-package library and executable exactly once.

It does not establish:

  • That the chosen claims and exclusions are appropriate for the project; that is reviewed with each rationale.

  • Exclusions do not permit a claimed module to import an excluded one (RG2004).

Review obligations the rule-coverage map associates with this rule (identifiers of the checker's Residual account):

  • R-QUALIFY: the checker's detection is qualified for this invocation, toolchain and capability

  • R-INTENT: the proposition expresses the intended requirement, with its quantifiers, hypotheses and limits

  • R-INVARIANT: the intended invariants, write paths and callers are all covered by proof-bearing interfaces

Every accepted result lists all residual obligations as open, whatever rules it checked: R-INTENT, R-INVARIANT, R-LAWS, R-BOUNDARY, R-NONVACUITY, R-DOC, R-COST, R-QUALIFY (and R-GRAPH for a serialized-graph claim). A listed identifier is an open obligation, never a completed review.

Every accepted result also relies on these trusted mechanisms (the checker's Trusted account), which no rule verifies:

  • toolchain: Lean elaborator, kernel and compiler at the snapshot's toolchain identity

  • acquisition: manifest parsing, Lake loading, and source, configuration and dependency acquisition

  • extraction: environment extraction, compiler and worker processes, and JSON transport

  • runtime: native runtime and every execution boundary reported as trusted

Configuration and exceptions🔗

The manifest is the configuration; there is no flag that accepts an invalid manifest. --manifest PATH and --project DIR select which files are audited, not how strictly.

lake lint exits 2 (INVALID CONFIGURATION) when only this rule rejects.

Limitations and unsupported cases🔗

Executable-only packages are valid Lean projects but unsupported by manifest schema 2.

The editor never guesses an omitted project scope.
