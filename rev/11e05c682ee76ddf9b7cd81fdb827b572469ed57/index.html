 Regula rule reference🔗

Development documentation generated from commit 11e05c682ee7 with Lean 4.34.0; linter version unreleased (no released package). Moving route: /regula/dev/. Snapshot route for this commit: /regula/rev/11e05c682ee7…/. Once this commit is published, its snapshot is kept by every later deployment. See versions and evidence.

Regula is a strict linter for Lean 4 projects. This reference explains every diagnostic it reports: what triggers it, why it matters, how to fix it, a checked example produced by the real checker, and exactly what a passing result does and does not establish.

If you followed a diagnostic link. Every Regula diagnostic carries a stable rule ID such as RG1001 (editor code Regula.RG1001) and ends with its explanation URL, for example https://rbeauchamp.github.io/regula/dev/rules/RG1001/. In VS Code the infoview's View explanation link opens the same page. The page's ID is the diagnostic's ID.

Reading a result. A finding's impact is either a violation, which makes the result FAIL, or incomplete, which means required evidence is missing and the result is INCOMPLETE. Neither is accepted. A passing result is mechanical: every rule page lists the review obligations it leaves open.

Find a rule. The rule index lists all 21 rules with filters by category, evidence mode and availability; it needs no JavaScript. The search box searches rule IDs, titles and page text.

Adopt and learn. Adoption guide (installation, lake lint, editor feedback and CI); the standard; compliance checklist; rule coverage and residual obligations; how this site is built and published.

Versions. This is development documentation; no package has been released. See versions and evidence for the exact build identity and the route policy.
